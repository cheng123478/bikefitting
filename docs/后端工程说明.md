# Aries 工程说明文档

## 项目概述

Aries 是一个基于 Spring Boot 3.5.10 的用户认证与管理系统，采用 Java 17 开发。项目提供完整的用户注册、登录、权限管理、文件上传等功能，适用于需要用户认证的Web应用。

### 技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Spring Boot | 3.5.10 | 基础框架 |
| Spring Security | 6.x | 安全认证 |
| Spring Data JPA | - | 数据持久化 |
| MySQL | 8.x | 关系型数据库 |
| Redis | - | 缓存与会话管理 |
| Hutool | 5.8.38 | 工具类库 |
| Fastjson2 | 2.0.57 | JSON序列化 |
| Log4j2 | 2.25.0 | 日志管理 |
| JOSE4J | 0.9.6 | JWT令牌生成与验证 |
| 腾讯云COS | 5.6.227 | 对象存储 |

## 核心模块详解

### 1. 用户认证模块 (Security)

#### 1.1 Spring Security 配置

**文件位置**: `config/SecurityConfig.java`

**实现功能**:
- 基于JWT的无状态认证
- 支持密码登录和短信验证码登录两种方式
- 自定义认证失败、拒绝访问、登出成功等处理器

**安全配置**:
```yaml
# 白名单路径
/user/login          # 密码登录
/user/login/sms      # 短信登录
/user/refresh        # Token刷新
/sms/send            # 发送短信
/resource/**         # 静态资源
```

**注意事项**:
- 使用 `SessionCreationPolicy.STATELESS` 实现无状态会话
- 禁用CSRF保护，前后端分离项目通常不需要
- 每个用户请求都需要携带 `Authorization: Bearer <token>` 请求头

#### 1.2 JWT 令牌机制

**文件位置**: `security/jwt/JwtUtil.java`

**Token 类型**:

| Token类型 | 有效期 | 用途 | 包含信息 |
|-----------|--------|------|----------|
| Access Token | 2小时 | 访问API | 用户ID、User-Agent MD5、基本信息 |
| Refresh Token | 7天 | 刷新Access Token | 用户ID、Token版本 |

**算法**: RSA-SHA256 非对称加密

**核心方法**:
- `createAccessToken()`: 创建访问令牌
- `createRefreshToken()`: 创建刷新令牌
- `parseToken()`: 解析并验证令牌
- `getIdFromToken()`: 从令牌中获取用户ID

**注意事项**:
1. **密钥生成**: 运行 `JwtUtil.main()` 方法生成公钥和私钥对
2. **密钥配置**: 将生成的密钥对配置到 `application.yml` 环境变量中
3. **Token刷新**: Access Token过期后，前端需调用 `/user/refresh` 接口使用Refresh Token获取新的Access Token
4. **设备绑定**: Access Token包含User-Agent的MD5值，防止Token被盗用

#### 1.3 JWT 过滤器

**文件位置**: `security/jwt/JwtFilter.java`

**工作流程**:
1. 检查请求是否在白名单中，是则放行
2. 从请求头提取 `Authorization` 信息
3. 验证Token有效性（签名+过期时间）
4. 验证User-Agent是否匹配（防止Token盗用）
5. 从Redis加载用户信息到Security上下文
6. 滑动窗口续期Redis会话时间

**注意事项**:
- Token过期返回 401 错误码
- Redis中找不到用户信息返回 "会话已失效"
- 每次有效请求都会续期Redis会话

### 2. 用户管理模块

#### 2.1 用户实体

**文件位置**: `entity/User.java`

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键（雪花算法生成） |
| phone | String | 手机号（唯一索引） |
| password | String | 密码（BCrypt加密） |
| name | String | 昵称 |
| avatar | String | 头像路径 |
| birthday | LocalDate | 生日 |
| email | String | 邮箱（唯一索引） |
| gender | Byte | 性别 |
| location | String | 地址 |
| registrationTime | LocalDateTime | 注册时间 |
| loginFailureCount | int | 登录失败次数 |
| isDeleted | Boolean | 是否注销 |
| deleteTime | LocalDateTime | 注销时间 |
| oldPhone | String | 注销前手机号（用于15天内限制重新注册） |
| accountNonExpired | boolean | 账号是否过期 |
| accountNonLocked | boolean | 账号是否锁定 |
| credentialsNonExpired | boolean | 凭证是否过期 |
| enabled | boolean | 是否可用 |
| lockTime | LocalDateTime | 锁定时间 |

#### 2.2 用户注册与登录

**文件位置**: `user/service/UserService.java`

**核心算法 - 注册与登录一体化**:

```java
public User registAndLogin(String phone)
```

**处理流程**:

1. **纯新用户**:
   - 创建新用户记录
   - 使用雪花算法生成ID
   - 设置默认昵称 "骑士" + 手机号后4位
   - 初始化安全状态（非锁定、已启用）

2. **已注销用户**:
   - 注销时间 < 7天: 自动恢复账号，取消注销标记
   - 注销时间 ≥ 7天: 旧账号手机号移至 `oldPhone` 字段，创建新账号

3. **正常活跃用户**:
   - 检查账号锁定状态
   - 自动解锁：锁定时间已过当天则自动解锁

**并发处理**:
- 使用 `synchronized (phone.intern())` 防止并发创建重复用户
- 双重检查机制确保数据一致性

#### 2.3 账号安全机制

**文件位置**: `user/service/UserService.java`

**登录失败锁定**:
- 失败次数达到 5 次 (常量: `USER_LOCK_LOGIN_FAIL_COUNT`)
- 自动锁定账号
- 第二天自动解锁（通过定时任务或登录时检查）

**自动解锁检查**:
```java
private void processUserLockStatus(User user)
```

**注意事项**:
- 用户登录失败时需要维护 `loginFailureCount` 字段
- 锁定后第二天（`lockTime.toLocalDate() < LocalDate.now()`）自动解锁

#### 2.4 账号注销机制

**文件位置**: `user/service/UserService.java`

**注销流程**:
1. 标记 `isDeleted = true`
2. 记录 `deleteTime` 为当前时间
3. 将手机号移至 `oldPhone` 字段
4. **不删除**数据库记录，仅标记

**恢复机制**:
- 7天内重新登录：直接恢复账号，取消注销标记
- 7天后登录：旧账号手机号清空，创建新账号

**注意事项**:
- 注销后用户需重新注册/登录
- 7天内保留数据恢复能力
- 符合GDPR等隐私保护法规要求

#### 2.5 定时清理任务

**文件位置**: `user/task/AccountCleanupTask.java`

**任务说明**:
- **执行时间**: 每天凌晨3点
- **清理对象**: 注销超过7天的账号
- **清理操作**: 将手机号设为NULL，实现数据匿名化

**优化建议**（代码注释中已提供）:

1. **索引优化**:
```sql
ALTER TABLE `usr_user` ADD INDEX `idx_cleanup` (`is_deleted`, `delete_time`);
```

2. **分批处理**:
- 每次处理1000条记录
- 避免长事务锁表
- 批次间休眠100ms释放资源

3. **冷热数据分离**（亿级用户）:
- 活跃用户保留在主表 `usr_user`
- 注销用户转移到历史表 `usr_user_history`
- 物理删除提升主表性能

### 3. 短信服务模块

#### 3.1 短信发送

**文件位置**: `sms/service/SmsService.java`

**第三方服务**: 阿里云短信服务（或其他短信服务商）

**核心功能**:
- 发送6位随机数字验证码
- 验证码缓存到Redis（5分钟有效期）
- 支持验证码验证（验证后立即删除）

**Redis配置**:
```yaml
# 验证码缓存Key
aries:sms:code:{phone}

# 有效期
5分钟
```

**注意事项**:
1. 验证码生成使用 `RandomUtil.randomNumbers(6)`
2. 验证通过后立即删除Redis中的验证码（一次性使用）
3. 发送失败需要记录详细日志

### 4. 数据加密模块

#### 4.1 RSA 加密

**文件位置**: `util/EncryptUtil.java`

**用途**:
- 前端使用公钥加密敏感数据（密码）
- 后端使用私钥解密

**密钥生成**:
```java
EncryptUtil.main()  // 运行生成RSA密钥对
```

**算法参数**:
- 算法: RSA
- 密钥长度: 2048位
- 填充方式: PKCS1Padding

**注意事项**:
- 私钥保密，只存储在服务器环境变量中
- 公钥公开，提供给前端使用
- 前端加密后的数据需Base64编码传输

## 安全注意事项

### 1. 密钥管理
- JWT密钥对（RSA 2048位）必须保密存储
- RSA解密私钥不能暴露给前端
- 建议定期轮换密钥

### 2. 密码安全
- 使用BCrypt加密存储（Spring Security默认）
- 前端RSA加密后传输
- 不要在日志中输出明文密码

### 3. Token安全
- Access Token有效期2小时
- Refresh Token有效期7天
- Token过期后强制重新登录
- Token绑定User-Agent防止盗用

### 4. 接口安全
- 所有业务接口需要认证
- 使用HTTPS传输
- 防止SQL注入、XSS攻击
- 限制请求频率

### 5. 数据安全
- 敏感数据脱敏处理
- 定期备份
- 合规处理注销用户数据

## 常见问题

### 1. Token过期问题
**问题**: Access Token过期后无法访问接口

**解决方案**:
1. 前端监听401响应
2. 使用Refresh Token调用 `/user/refresh` 接口
3. 获取新的Access Token后重试请求

### 2. 并发创建用户
**问题**: 多个请求同时使用同一个手机号注册

**解决方案**:
- 使用 `synchronized (phone.intern())` 保证原子性
- 双重检查机制
- 数据库唯一索引兜底

### 3. 性能优化
**建议**:
- 添加数据库索引
- 使用Redis缓存热点数据
- 分页查询
- 异步处理耗时操作

### 4. 大量注销用户清理
**问题**: 定时任务清理大量注销用户导致性能问题

**解决方案**:
- 分批处理（每次1000条）
- 添加索引 (`idx_deleted_time`)
- 低峰期执行（凌晨3点）
- 批次间休眠释放资源
